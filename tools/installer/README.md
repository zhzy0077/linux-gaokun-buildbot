# Gaokun Fedora 44 RPM installer

The desktop launcher opens the official Anaconda WebUI with a Fedora Workstation
DNF payload. Fedora supplies desktop packages; the USB repository supplies the
Gaokun kernel, modules, firmware and platform RPMs.

## Prepare the USB

Install Anaconda's graphical/live launcher, Zenity, polkit, Cockpit storage,
`udisks2-btrfs`, and `createrepo_c` in the working Gaokun USB system. Before
updating an existing image, keep read-only Btrfs snapshots and a verified ESP backup.

| Source | Location on the USB |
| --- | --- |
| `interactive-defaults.ks` | `/usr/share/anaconda/interactive-defaults.ks` |
| `90-gaokun.conf` | `/etc/anaconda/conf.d/90-gaokun.conf` |
| `gaokun-install` | `/usr/local/bin/gaokun-install` (0755) |
| `gaokun-install-backend` | `/usr/local/libexec/gaokun-install-backend` (0755) |
| `gaokun-install.desktop` | `/usr/share/applications/gaokun-install.desktop` |

Place `gaokun_installer.py`, `platform-cmdline`, `rpm-manifest.json` and
`test-target.json` in `/opt/installer/`. Copy the target RPMs into
`/opt/installer/repo/` and generate its metadata with `createrepo_c`.
`rpm-manifest.json` contains `kernel_release` and a `sha256` object mapping every
local RPM filename to its digest. Keep machine-specific target data outside Git:

```json
{
  "source_uuid": "USB Btrfs UUID",
  "source_serial": "USB disk serial",
  "target_serial": "target disk serial",
  "root_partuuid": "existing Fedora partition GUID",
  "root_size_bytes": 0,
  "old_root_uuid": "root=UUID value in the old Fedora BLS entries",
  "old_partition_fs_uuid": "UUID reported by blkid for the raw target partition",
  "esp_partuuid": "existing EFI partition GUID",
  "esp_uuid": "existing FAT filesystem UUID",
  "old_boot_token": "32 hexadecimal characters from the old Fedora BLS entries"
}
```

For an existing LUKS installation, `old_partition_fs_uuid` is the **LUKS UUID**,
while `old_root_uuid` is the **decrypted Btrfs UUID**. On an unencrypted Btrfs
partition they are equal; older plans may omit `old_partition_fs_uuid` in that case.

Preflight verifies the running USB, target serial, partition identities and size,
and local RPM digests. A replaced filesystem requires a new reviewed plan.
The launcher is scoped to replacing an existing Fedora partition, not arbitrary
partition creation or resizing.

## Storage workflow

1. Open the integrated storage editor and identify the target partition against
   the plan. Review its immediate-format confirmation before applying changes.
2. Format only that partition as LUKS2 + Btrfs, keeping its partition GUID and
   geometry. Enter the password locally; leave **Store passphrase** unchecked.
3. Create `root` and `home` subvolumes and assign `/` and `/home`. Reuse the existing
   ESP at `/boot/efi` with formatting disabled.
4. Check Anaconda's final mount assignments before starting installation.

The editor applies changes immediately. Windows, recovery partitions and the ESP
retain their filesystems. The generated Kickstart uses `ignoredisk` and
`clearpart --none`; storage assignments use WebUI's MANUAL path. Fedora 44 WebUI 68
cannot handle the CUSTOM object generated by Kickstart `part`/`btrfs` directives.

During `%pre-install`, the helper validates the mounted target and backs up the
entire ESP to the USB. It removes only the old Fedora entries/token directory
identified by the plan, after checking every entry's root UUID. Microsoft files
and vendor firmware remain outside that cleanup. The ESP must then have 128 MiB
free for the new boot files; old diagnostic copies should be archived during a
reviewed reinstall rather than accumulated indefinitely.

## Desktop and boot policy

The launcher offers two unchecked options: retain the installation environment's
NetworkManager connections (including saved Wi-Fi credentials), and enable SSH
on the installed system. The privileged backend records these booleans in
`/run/gaokun-installer/policy.json`; finalization applies them to the verified new
root after Anaconda's network/service setup. With no opt-in, copied connection
keyfiles are removed and SSH remains disabled. Users reconnect through GNOME
Initial Setup, which also creates their account.

`liveinst` uses `LIVECMD` to launch Anaconda with `--profile=fedora-workstation`.
The interactive defaults select the DNF payload; `--liveinst` and `--kickstart`
are omitted to preserve package installation and interactive operation.

The mandatory `%post` installs systemd-boot with `--no-variables`, creates a
crypt-enabled initramfs and BLS entries using the actual root/LUKS UUIDs and Gaokun
DTB. GRUB-specific kernel-install plugins are masked for this configuration.
GPU firmware and the early PCM override are checked against nonempty extracted
initramfs members. Unused RPM-generated initrd copies are removed only after
checking all BLS references. The LUKS password is never embedded in these files.

When replacing an earlier RPM revision of the *same* kernel release, use a
one-transaction `--setopt=installonlypkgs=` override: both revisions own identical
kernel/module paths. Keep the global DNF install-only policy unchanged. Old image
service overrides under `/etc/systemd/system` must be backed up and reviewed when
switching to RPM-owned platform services.

## Validation

Run the repository tests and Fedora 44 `ksvalidator`, including the generated
storage fragment. Native platform, display and audio checks are documented in
[the platform guide](../../docs/fedora_platform_rpm_zh.md).

A real Gaokun RPM installation has completed LUKS unlocking and GNOME login while
preserving partition geometry and Microsoft EFI files. The revised encrypted-root
reinstall guard has regression coverage; the complete reinstall remains a separate
end-to-end test. Storage formatting and boot unlocking require local confirmation.
